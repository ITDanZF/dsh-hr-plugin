# 通用求职简历要素

本文固化一份通用求职简历应包含的信息。它是字段来源；当前插件已经按它实现编辑、预览和 PDF。

范围是投递给雇主的求职简历，不是学术履历。论文、课题和专利只在研究或知识产权岗位作为可选补充，不进入默认正文。求职信是另一份文件，不并进简历板块。

依据：

- 开放数据模型：[JSON Resume](https://jsonresume.org/docs/guides/schema)、[Reactive Resume](https://github.com/amruthpillai/reactive-resume/blob/main/skills/resume-builder/references/schema.md)
- 中文编辑器与指南：[seaeam/resume](https://github.com/seaeam/resume)、[bufancv/resume-guide](https://github.com/bufancv/resume-guide)、[AppleCG/resume-maker](https://github.com/AppleCG/resume-maker)，以及超级简历、TalenCat 的内置模块
- 招聘网站表单：智联招聘的基本信息、求职意向、教育、工作、项目、自我评价
- 国际简历：Europass、LinkedIn 资料板块、Monster、Indeed、美国劳工部 2026 简历指南，以及耶鲁、威斯康星等就业中心的字段说明

## 使用约定

每个字段用下面四级标注：

| 级别 | 含义 |
| --- | --- |
| 必填 | 没有它，简历无法被联系或无法识别是谁 |
| 建议 | 通用简历应当出现，空着会明显变弱 |
| 可选 | 有内容且与岗位相关时再写 |
| 仅网申 | 招聘网站表单会要，纸质或 PDF 简历默认不印 |

书写约定：

- 经历一律时间倒序。仍在进行的条目不写结束日期。
- 社招把工作经历放在教育前面。应届把教育、实习或项目提前。
- 每段经历大约三到五条要点。用动作加对象、方法和结果来写，能用数字就用数字。
- 篇幅一到两页。模块标题用常见名称，方便人和解析系统识别。
- 同一件事只出现在一个模块里。工作里已经写过的项目，不要在项目模块再抄一遍。

## 推荐顺序

社招：

1. 基本信息
2. 职业摘要
3. 工作经历
4. 项目经历
5. 教育背景
6. 技能
7. 证书与荣誉
8. 语言，有则放在技能附近

应届，经历比较均衡时：

1. 基本信息
2. 求职意向
3. 教育背景
4. 实习与项目
5. 技能
6. 荣誉
7. 校园与志愿

有突出实习、项目或技能的应届生，可以把技能或实习放到教育前面。求职意向如果已经写在页眉的一句话头衔里，正文不必再重复一整块。

## 基本信息

| 字段 | 级别 | 说明 |
| --- | --- | --- |
| 姓名 | 必填 | 与日常使用的姓名一致 |
| 手机 | 必填 | 保持畅通 |
| 邮箱 | 必填 | 用姓名相关的常规邮箱，不用网名邮箱 |
| 现居城市 | 建议 | 写到城市或区。不写街道和门牌 |
| 一句话头衔 | 建议 | 目标职位或当前职业身份，例如「后端工程师」 |
| 个人链接 | 可选 | 可重复。每条含平台名、账号、网址。常见平台：个人网站、LinkedIn、GitHub、作品集 |
| 证件照 | 可选 | 默认不放。设计、演艺，或招聘方明确要求时再放 |

## 求职意向

求职意向回答「这次想找什么」。职业摘要回答「为什么匹配」。两者可以同时存在，也可以只保留页眉里的一句话头衔。

| 字段 | 级别 | 说明 |
| --- | --- | --- |
| 目标岗位 | 建议 | 与本次投递的岗位一致，避免「管培生」「多个方向均可」这类空泛写法 |
| 期望行业 | 可选 | 例如互联网、制造。跨行业投递时再写 |
| 期望城市 | 可选 | 可以多个。与现居城市不同时才有必要单列 |
| 工作性质 | 可选 | 全职、兼职、实习 |
| 期望薪资 | 仅网申 | 写区间或「面议」。纸质简历默认不印 |
| 到岗时间 | 仅网申 | 例如随时、两周内。纸质简历默认不印 |
| 求职状态 | 仅网申 | 在职、离职、应届。纸质简历默认不印 |

## 职业摘要

| 字段 | 级别 | 说明 |
| --- | --- | --- |
| 摘要正文 | 建议 | 两到三句。说明年限或阶段、核心能力、和目标岗位的匹配点 |

有工作经验时写职业摘要。应届或转行时，摘要可以和求职意向一起用，重点仍是匹配点。

自我评价并入这一段。不另开一栏堆「学习能力强」「抗压能力好」这类无法核对的形容词。

## 工作经历

实习与正式工作使用同一套字段。可以放在同一模块，标题写「工作与实习经历」；应届生也可以把实习单独成模块。

每条经历：

| 字段 | 级别 | 说明 |
| --- | --- | --- |
| 公司或机构 | 必填 | 对外使用的名称 |
| 职位 | 必填 | 当时的岗位名称 |
| 地点 | 建议 | 城市。远程工作写「远程」 |
| 开始时间 | 必填 | 年到月即可 |
| 结束时间 | 建议 | 仍在职则留空 |
| 行业或职责概述 | 可选 | 一句话。职位名称看不出职责范围时再写 |
| 公司网址 | 可选 | 公司不为人知、或作品和公司强相关时再写 |
| 成果要点 | 建议 | 三到五条。动作开头，写清做了什么、结果是什么 |
| 关键词 | 可选 | 与岗位相关的工具、领域词，便于检索。不单独铺成一段形容词 |

兼职、军旅、董监事、职业空窗可以沿用这套字段，只在和目标岗位有关时保留。早期、关联弱的经历少写要点，甚至只保留公司、职位和时间。

## 项目经历

技术、产品、设计、运营等靠作品说话的岗位建议单列。已经在工作要点里写清楚的项目，不必再复制一份。

每条项目：

| 字段 | 级别 | 说明 |
| --- | --- | --- |
| 项目名称 | 必填 | |
| 角色 | 建议 | 负责的部分，而不是只写「参与」 |
| 所属组织 | 可选 | 公司项目写公司；个人或课程项目写「个人」或学校 |
| 类型 | 可选 | 例如商业项目、毕业设计、开源 |
| 开始时间 | 建议 | 年到月 |
| 结束时间 | 建议 | 进行中则留空 |
| 概述 | 建议 | 一两句：背景、目标 |
| 要点 | 建议 | 你做了什么、用了什么方法、结果是什么 |
| 技术或方法关键词 | 可选 | 与技能模块呼应，不把整份技能表再贴一遍 |
| 链接 | 可选 | 仓库、演示、作品地址 |

## 教育背景

按最高学历在前排列。高中及更早的教育默认不写。

每条教育：

| 字段 | 级别 | 说明 |
| --- | --- | --- |
| 学校 | 必填 | 与毕业证书一致。学校更名时可注曾用名 |
| 学历 | 必填 | 例如本科、硕士 |
| 专业 | 建议 | 有辅修或第二专业，且与岗位相关时一并写出 |
| 开始时间 | 建议 | |
| 结束或毕业时间 | 建议 | 在读写预计毕业时间 |
| 地点 | 可选 | 学校所在城市。城市本身已经说明学校时可以省略 |
| 学历性质 | 可选 | 全日制、自考、成人教育。非全日制时建议标明 |
| 成绩 | 可选 | GPA 或排名。应届且明显有优势时再写，例如 3.5/4.0、前 10% |
| 相关课程 | 可选 | 应届、且课程名能对上岗位时写三到五门。不写「专业导论」这类公共课 |
| 交换或游学 | 可选 | 学校、时间、和岗位相关的收获 |

毕业设计题目只在应届、且题目本身就是相关项目时，放到项目模块，不堆在教育条目里。

## 技能

技能按岗位相关性排序，写成可核对的工具和技术，不写「沟通能力」「责任心」。

每组技能：

| 字段 | 级别 | 说明 |
| --- | --- | --- |
| 分组名称 | 建议 | 例如编程语言、设计工具、数据分析 |
| 熟练度 | 可选 | 精通、熟练、了解。没有把握就只列名称 |
| 关键词 | 建议 | 具体名称，例如 TypeScript、Figma、SQL |

软技能通过经历要点体现。

## 语言

和技能分开。涉外、外语或跨地区岗位建议写；其他岗位有证书或工作语言要求时再写。

| 字段 | 级别 | 说明 |
| --- | --- | --- |
| 语种 | 必填（本模块出现时） | 含母语以外的工作语言 |
| 熟练度或成绩 | 建议 | 例如熟练、流利，或雅思 7.0。不默认拆成听、说、读、写 |

## 证书

职业资格、执照、平台认证放这里。校园奖学金放荣誉，不放证书。

| 字段 | 级别 | 说明 |
| --- | --- | --- |
| 名称 | 必填 | |
| 颁发机构 | 建议 | |
| 获得时间 | 建议 | |
| 有效期 | 可选 | 有到期日的执照、安全认证要写 |
| 证书编号 | 可选 | 需要核验时再写 |
| 验证链接 | 可选 | |

过期且与岗位无关的证书不写。

## 荣誉

| 字段 | 级别 | 说明 |
| --- | --- | --- |
| 名称 | 必填 | |
| 颁发方 | 建议 | |
| 时间 | 建议 | |
| 说明 | 可选 | 一句话，说明范围或含金量，例如「全校 3 人」 |

非应届生不罗列与岗位无关的校园奖项。

## 校园、社团与志愿

组织、角色、地点、起止时间、要点，字段与工作经历相同。只保留能说明责任、协作或岗位相关能力的条目。单纯的成员身份可以只保留组织和时间。

## 兴趣

短列表。只在爱好能说明岗位相关特质时保留，例如写作岗位的长期写作、设计岗位的摄影。不写「读书、旅游、音乐」这类无法区分的爱好。

## 发表与专利

仅研究、高校或知识产权相关岗位使用。不把完整论文目录放进通用简历。

| 字段 | 级别 | 说明 |
| --- | --- | --- |
| 名称 | 必填 | |
| 类型 | 建议 | 论文、会议报告、专利 |
| 发表处或权利人 | 建议 | 期刊、会议，或专利局 |
| 时间 | 建议 | |
| 链接或标识 | 可选 | 网址、DOI、专利号 |

## 推荐人

默认不出现，或只写「如需要可提供」。

需要写出具体推荐人时：

| 字段 | 级别 | 说明 |
| --- | --- | --- |
| 姓名 | 必填 | 事先征得同意 |
| 关系 | 建议 | 例如前直属上级 |
| 单位与职位 | 建议 | |
| 电话或邮箱 | 可选 | 默认不收集。对方明确同意再写 |

## 求职信

求职信不是简历模块。它针对某一家公司和某一个岗位，说明动机和匹配理由，通常另行提交。简历里不留「求职信正文」字段。

## 不进入默认简历的信息

这些字段会出现在部分国内招聘网站的注册或网申表单里。通用简历、右侧预览和 PDF 默认都不收集、不展示：

- 身份证号
- 街道、门牌等详细住址
- 婚姻、生育状况
- 身高、体重
- 政治面貌
- 民族、籍贯
- 出生日期

年龄只在网申明确要求时填写，不作为简历正文的默认字段。

## 与当前数据结构的差距

当前简历文档定义在 [src/domain/index.ts](../src/domain/index.ts)。本文只记录差距，不改类型。

已经覆盖：

- 基本信息：姓名、一句话头衔、邮箱、电话、城市、职业摘要
- 四种段落：工作经历、教育、项目、技能
- 每段段落：标题、副标题、开始时间、结束时间、要点列表

尚未覆盖，后续做原型时再决定是否加字段：

| 本文板块 | 现有数据里缺什么 |
| --- | --- |
| 基本信息 | 个人链接（平台、账号、网址）、证件照 |
| 求职意向 | 目标岗位以外的行业、期望城市、工作性质；薪资、到岗时间、求职状态即使以后要，也只属于网申 |
| 工作经历 | 地点、行业概述、公司网址、关键词没有独立字段。地点和公司目前只能挤进标题或副标题 |
| 项目经历 | 角色、所属组织、类型、链接、技术关键词没有独立字段 |
| 教育背景 | 学历、专业、地点、学历性质、成绩、课程、交换没有独立字段 |
| 技能 | 分组、熟练度、关键词没有独立字段。现在只能写成一段的标题和要点 |
| 语言 | 整块没有 |
| 证书 | 整块没有 |
| 荣誉 | 整块没有 |
| 校园、社团与志愿 | 整块没有。若暂时要记，只能先借用工作经历这一类 |
| 兴趣 | 整块没有 |
| 发表与专利 | 整块没有 |
| 推荐人 | 整块没有。默认本来也不展示 |
