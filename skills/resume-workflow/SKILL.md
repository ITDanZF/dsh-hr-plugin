# 简历工作流

本轮若尚未读取 `resume_read_manual` 的 `manual`，先读取；若尚未读取 `resume_read_workflow` 的 `workflow`，再读取。然后调用 `resume_read`，以返回的 `document` 为当前草稿；空记录视为一份空简历。不要把右侧面板的示例草稿当作会话数据。

## 判断请求

- 用户要评价、诊断或改写建议，先基于现有内容回答。只有用户要求直接改当前简历时才写入。
- 用户要创建、补全、纠错、润色或按岗位定制正文，加载 `resume-edit`。
- 用户要添加、隐藏、自定义或排序表单模块，加载 `resume-edit`；侧栏版式的模块位置也由该技能处理。
- 用户要调整预设、布局、字体、颜色等纸面，加载 `resume-template`。
- 用户明确要文件，加载 `resume-export`。若同时要修改和导出，先完成修改，再导出最终状态。
- 混合请求按依赖顺序处理；正文、纸面和导出各用所属技能及工具。所需技能或工具不可用时，说明受阻部分，不用其他类别的工具冒充。

## 执行与交付

从 `document` 与用户提供的材料中区分已知事实、待确认信息和纯写作建议。关键事实缺失时可以先完成不依赖它的部分，再集中询问；不得补造任职、学历、数字、证书、联系方式或推荐人资料。用户提供的岗位描述只用于确定相关性，不自动当作本人经历。

每次只发起一个写入或导出工具调用，读完返回的 `document`、`path` 或 `error` 再进行下一步；后一步以最新 `document` 的条目 `id` 和内容为准。`ok: false` 时告知 `error`，停止依赖该步骤的后续操作。完成后核对返回数据与请求，说明完成了什么、仍缺什么。正文或纸面变更请用户查看右侧简历页，不声称已替用户打开面板，也不声称已验证打印效果。
